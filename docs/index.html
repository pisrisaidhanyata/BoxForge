About the Project

BoxForge is a minimal container runtime developed in C on Linux. It demonstrates how operating-system features can create an isolated environment for running a process.

The project uses Linux namespaces, a minimal root filesystem, BusyBox utilities, and cgroups v2 resource controls where the environment supports them.

BoxForge is designed for learning and demonstrating container fundamentals. It is not intended to replace production tools such as Docker.

Project Objectives

Process Isolation

Explore Linux PID namespaces and isolated process views.

Filesystem

Run commands using a minimal root filesystem.

Resource Control

Apply CPU and memory limits using cgroups v2 when supported.

Linux Concepts

Understand how operating-system mechanisms support containerization.

Project Architecture

BoxForge receives a command, prepares an isolated environment, starts the requested program, and cleans up after it exits.

User Command
↓
BoxForge Runtime (C)
↓
Linux Namespaces
↓
Minimal Root Filesystem
↓
CPU and Memory Controls (cgroups v2)
↓
Run Program and Clean Up

Resource controls depend on the Linux environment and cgroup delegation permissions. BoxForge reports an error if it cannot apply its configured resource limits.

How to Run BoxForge

BoxForge is a Linux C program. Run it in a suitable Linux environment such as your configured Ubuntu/WSL environment. GitHub Pages hosts this website; it does not run the container.

1. Clone the repository

$ git clone https://github.com/pisrisaidhanyata/BoxForge.git
$ cd BoxForge

2. Build the project

$ make clean
$ make

3. Start the container

$ sudo ./boxforge /bin/bash

The root filesystem, BusyBox installation, required Linux features, and cgroup permissions must be configured correctly. Follow the repository README for environment requirements.

Container Demonstration

Sample Output from the Ubuntu Prototype

The following examples illustrate commands used inside the BoxForge container. The output is shown for demonstration; this webpage does not execute the commands.

1. Check the process ID

bash-5.3# echo $$
1

The shell displays PID 1 inside the PID namespace, as observed in the project demonstration.

2. Check the hostname

bash-5.3# hostname
boxforge

This demonstrates the container hostname configured by the project.

3. Check the current directory

bash-5.3# pwd
/

The shell's current working directory is the root directory of the container environment.

4. List the root filesystem

bash-5.3# ls /
bin  dev  etc  lib64  proc  sys  tmp  usr

These entries show the minimal root filesystem used by the demonstration.

5. Inspect processes

bash-5.3# ps

This command displays the processes visible inside the container. The exact output depends on the running processes and BusyBox configuration.

6. Exit the container

bash-5.3# exit
BoxForge: Container stopped

Exiting the shell returns control to the host terminal and allows the runtime to perform its cleanup.

7. Check the resource controls

$ sudo ./boxforge /bin/bash
BoxForge: Creating isolated environment...
BoxForge: Container process started
BoxForge: Memory limit set to 512 MiB
BoxForge: CPU quota set to 50%
BoxForge: Starting container

This sample reflects the successful output shown by the current prototype. Actual process IDs and messages may vary.
